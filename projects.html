ProReady

What it does: A study platform for certification exams: multi-subject course packs, spaced-repetition review (FSRS), an instructor review queue and encrypted content storage. Built with Claude under my direction.

First test run: a full CompTIA A+ course built on it to prove the platform — all 9 exam domains, two timed 90-question mock exams, 28 diagrams and 24 study games.

Stack

Next.js, TypeScript, PostgreSQL, Prisma, systemd, git.

A real problem it solved: I traced a live outage to a test build written into the production folder while the health check stayed green, restored service, and approved two guards: separate test-build folders and a health check that verifies the build. I also found the backup restore test could pass with every course image missing, and rebuilt it to check every stored file and restore from the off-site copy.

Home server

What it does: A Linux Mint server that runs my apps, Docker services, local AI models and document archiving. Services start on boot under systemd, secrets live in HashiCorp Vault, and my phone reaches it over HTTPS on a private network.

Stack

Linux Mint, systemd, Docker, HashiCorp Vault, a private network, Ollama, Paperless-ngx.

A real problem it solved: Restarts kept failing with “unit not found” and “start request repeated too quickly.” I found services split across systemd's system and user managers plus a stray process holding a port — fixed both and documented which service lives where.

Lab notes: systemd · HTTPS to my phone · Docker and localhost · Secrets · DNS trap · Works on my machine

Home server lab notes

Short Linux admin write-ups from running my own server.

  • “Unit not found” doesn't always mean “not installed” — systemd's two managers, a stray process holding a port, and an error that pointed the wrong way.
  • Ending “cleartext not permitted” — real HTTPS from phone to home server — Private-network HTTPS with a real certificate — no IP baked into the app, no rebuilds.
  • Why my service couldn't see “localhost” inside Docker — Docker's port forwarding hid local requests — moved the service to a host systemd unit.
  • Keeping API keys out of plain text — Every API key in HashiCorp Vault — rotate from a screen, never shown back, unseals at boot.
  • The server that couldn't find itself — a DNS trap — A hand-managed resolver file from an old VPN fix — and why I didn't just undo it.
  • “Works on my machine” — why remote devices couldn't reach my tools — Links that only worked on the server — fixed with a same-address allow-list and a regression test.
