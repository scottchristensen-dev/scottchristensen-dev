The green health check that lied

A live outage the monitoring missed — and the backup test that couldn't fail.

Project: ProReady · built with Claude under my direction

← All projects

The problem

The live study site went down, but the health check stayed green. Monitoring said everything was fine.

What I found

A test build had been written into the production folder. The health check only asked “is the service running?” — not “is the right build being served?” So it kept passing while users got a broken site.

The fix

  • Restored service.
  • Test builds now go to their own folders, never production.
  • The health check now verifies the build itself, not just that the process is up.

Follow-up: the backup test that couldn't fail

While checking recovery, I found the backup restore test could pass with every course image missing — it only counted database rows. I had it rebuilt to check every stored file's existence and size, and to restore from the off-site copy.

Takeaway

A check that can't fail isn't a check. I test the tests.
