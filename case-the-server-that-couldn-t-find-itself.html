The server that couldn't find itself — a DNS trap

Before you undo something odd, find out why it's there.

← All projects

The problem

From the server, every request to its own private-network name failed (curl exit 6: couldn't resolve host). It looked like the phone link was down. It wasn't — the phone connected fine.

What I found

Months earlier, a VPN had broken name resolution, so the server's resolver file had been set by hand to public DNS servers only. Those servers don't know private-network names. The phone wasn't affected because it resolves names through its own private-network client.

The tempting fix — and why I didn't take it

Pointing the resolver back at the system default would have “fixed” it and quietly undone the VPN workaround. The safe fix is adding the private network's resolver at the top of the hand-managed file. I documented the trap so nobody loses another session to it.

Takeaway

Before you undo something odd, find out why it's there.
